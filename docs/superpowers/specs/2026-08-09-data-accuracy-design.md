# 趋势雷达数据准确性改造设计

## 目标

在不改变现有网页结构、导航、栏目和视觉布局的前提下，提高看板数字的真实性、可追溯性和失败可见性。系统不得使用固定分数、随机走势、零值或无依据默认值填补缺失数据。

## 基本原则

1. 没有数据就显示“数据暂缺”，不得硬凑。
2. 每个数字必须能追溯到来源、数据日期和抓取时间。
3. 旧数据可以保留，但必须显示真实数据日期，不得冒充当日数据。
4. 不同频率的数据按各自发布周期判断新鲜度，融资融券等 T+1 数据不视为异常。
5. 只有通过完整性、日期和合理性校验的数据才能参与评分与结论生成。
6. 本次不调整页面信息架构，只修改数据、算法和必要的状态文案。

## 数据模型

每类数据除业务值外，增加统一元数据：

- `source`：数据来源名称。
- `sourceDate`：该数值实际对应的交易日或统计期。
- `fetchedAt`：本次抓取时间。
- `status`：`valid`、`stale`、`missing` 或 `invalid`。
- `reason`：数据不可用或被降级的原因。

页面仍消费现有业务字段。元数据用于校验、评分和状态展示，避免大规模调整渲染结构。

## 数据采集与保留规则

当前阶段继续以 AKShare 及其聚合的公开市场数据为主要来源，同时预留未来多源交叉验证字段。

- 抓取成功且通过校验：写入新值及对应元数据。
- 抓取失败：业务值写为 `null`，状态写为 `missing`，不得写成 `0`。
- 数据日期落后但仍符合发布周期：保留真实日期，状态为 `valid`。
- 数据超过允许时效：可保留上次值供用户参考，但状态为 `stale`，不得参与当日评分。
- 数值不符合合理范围或字段结构变化：状态为 `invalid`，保留异常原因，不参与评分。
- 自动更新只有在核心指数数据有效时才发布新的报告日期；局部数据失败不覆盖为伪造值。

## 校验规则

校验分为四类：

1. 完整性：必需字段存在，且不是空值、非数值或无意义的零值。
2. 日期一致性：行情类数据对应同一交易日；低频数据使用自身统计期。
3. 合理范围：涨跌幅、指数点位、成交额、涨跌家数等满足基本边界。
4. 突变检查：与上一有效交易日相比出现极端变化时标记异常，而不是直接发布。

异常检查用于阻止明显错误，不用于修改真实市场数据。合理阈值集中配置，避免散落在抓取代码中。

## 雷达评分

删除日、周、月和基本面雷达中的固定分数。每个维度定义：

- 必需输入指标。
- 可选输入指标。
- 指标方向和归一化区间。
- 权重及最终评分公式。
- 最低完整性要求。

必需输入缺失或失效时，该维度不生成分数，页面显示灰色“暂无评分”。总分仅在核心维度达到最低完整性要求时生成，同时显示数据完整度。缺失维度不得通过重新分配权重制造一个看似完整的总分。

首期只为已有可靠数据的维度建立评分，包括指数表现、成交活跃度、市场广度、行业资金和杠杆资金。ETF、外资、情绪、宏观等维度在数据链路未验证前保持暂无评分。

## 走势图与历史数据

删除 `genTrend()` 产生的随机走势图。图表只使用实际历史记录：

- 有两个及以上有效历史点时绘制走势。
- 只有一个有效点时显示单点数值和日期。
- 没有有效点时显示“暂无历史数据”。
- 历史记录按来源日期去重，不将同一天的重复运行保存成多个交易日。

## 每日结论

保留当前结论展示区域，但结论必须从有效数据生成，结构为：

- 市场状态：根据有效评分及明确规则生成。
- 支持证据：最多三项实际指标，附数值及日期。
- 风险信号：仅列出已触发阈值的有效指标。
- 数据完整度：列出缺失或过期的关键数据。

证据不足时显示“有效数据不足，暂不形成判断”，不得使用固定描述补齐。

## 估值模型

保留 DCF、DDM、相对估值、蒙特卡洛和实物期权五类模型及现有页面结构。

- 行情或财务数据抓取失败时，相关参数保持空白并提示手工输入。
- 每个自动参数显示来源财报期或行情日期。
- 缺少模型必需参数时禁止计算目标价。
- 默认假设必须明确标记为“模型假设”，不得伪装成公司真实数据。
- 计算结果展示输入完整性；关键输入无效时不进入汇总结果。

## 页面状态

不新增页面或改变布局，只在现有组件内增加必要状态：

- 数据暂缺
- 数据已过期，并显示实际日期
- 数据异常，并显示简短原因
- 暂无评分
- 有效数据不足，暂不形成判断

状态色使用中性灰或警示色，不能沿用代表市场好坏的红绿颜色。

## 自动更新流程

每日任务执行顺序调整为：抓取原始数据、规范化、校验、计算派生指标、生成评分与结论、写入临时结果、执行最终完整性检查、发布 `js/data.js`。

若最终检查失败，任务应保留线上旧文件并返回失败状态。局部失败但核心数据有效时可以发布，同时在元数据中记录缺失项。

## 测试与验收

至少覆盖以下测试：

- 抓取失败不会产生零值、固定分数或随机走势。
- 非交易日不会生成新的报告日期。
- T+1 数据按真实日期展示且不会错误报警。
- 过期数据不参与当日评分。
- 雷达输入不足时显示暂无评分。
- 历史趋势完全来自已保存数据。
- 估值必需参数缺失时无法生成目标价。
- 页面在所有数据缺失时仍能正常打开，无脚本错误。

验收标准：项目中不存在用于生产展示的随机行情、固定雷达分数或无依据自动参数；任意展示数字均能确定来源日期和有效状态；缺失数据在页面上明确可见。

## 范围之外

本次不修改网页结构，不新增用户系统、关注列表、导出功能或新的市场数据栏目；不在首期引入付费数据源或复杂的双源仲裁。这些能力可在数据可信化完成后独立设计。
