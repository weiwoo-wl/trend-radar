# 盘中实时行情与行业资金流向设计

## 目标

修复现有“天数据”实时刷新功能，并在指数与成交额之后增加独立的行业资金流向区域。模块用于观察盘中市场强弱和行业资金方向，不把行情平台统计的主力净流入解释为机构真实账户交易。

## 本期范围

- 保留现有九个指数、全市场成交额和涨跌家数的两分钟刷新。
- 修复交易时段判断和自动启停。
- 新增申万行业涨跌幅、成交额、主力净流入及排名。
- 新增数据时间、延迟和非交易时段状态。
- 选择历史日期时禁止实时数据覆盖历史内容。
- 不新增宽基 ETF，不修改政策性资金模块，不制作未经验证的分钟历史曲线。

## 技术路线

网站继续部署在 GitHub Pages。浏览器在盘中直接读取东方财富公开行情接口，不引入服务器或数据库。该路线改造小、符合现有部署方式；接口不可用时通过保留上一笔有效数据和延迟提示降级。

GitHub Actions 继续负责日终数据，不承担分钟级刷新。将来若公开接口稳定性不足，再把实时数据迁移到独立后台服务，本期不提前建设。

## 数据口径

### 市场状态

- 九个指数点位、涨跌额和涨跌幅。
- 沪深北市场成交额。
- 上涨、下跌和平盘家数。

### 行业资金流向

- 使用同一行业分类口径返回的行业代码和名称。
- 展示行业涨跌幅、成交额、主力净流入金额和净流入占比（接口提供且通过校验时）。
- 页面明确标注“主力净流入为行情平台统计口径，不代表机构真实账户交易”。
- 成交额不等于资金净流入；本期不从成交额推算净买入。

## 页面结构

行业资金区域放在“天数据”的指数和成交额之后，包括：

1. 行业概览：上涨行业数、下跌行业数、净流入行业数、数据时间。
2. 行业排行：涨幅榜、主力净流入榜、主力净流出榜。
3. 行业资金图：用颜色区分净流入和净流出，金额统一为亿元。
4. 行业明细表：默认展示全部行业，可按主力净流入排序。
5. 口径说明：解释数据来源、更新时间和统计限制。

页面沿用现有卡片、表格和 ECharts 风格，不改变导航结构。

## 更新流程

1. 交易日 9:25–11:30、13:00–15:05 自动运行，每两分钟请求一次。
2. 午休暂停请求，下午开盘后恢复；收盘后停止定时器并保留最后有效快照。
3. 用户点击“实时”时，非交易时段允许尝试刷新一次，同时显示“非交易时段”。
4. 用户选择历史日期后停止实时覆盖；返回“最新”后按当前时间决定是否恢复。
5. 每批数据在完整校验通过后一次性更新，避免页面出现一半新、一半旧的数据。

## 校验与异常处理

以下任一情况出现时拒绝整批行业数据：

- 响应为空或结构不符合预期。
- 行业数量明显不足。
- 行业代码或名称缺失、重复。
- 核心数值无法解析或超过合理范围。
- 数据更新时间早于当前页面已接受的快照。

请求失败时保留上一笔有效数据并显示“实时数据延迟”。连续失败不把字段写成零，也不清空页面。首次加载即失败时显示“暂未取得有效实时数据”。日志只记录必要的错误类型，不在页面中暴露接口内部信息。

## 模块边界

实时请求、交易时段、校验和状态管理集中在独立实时模块中；行业页面渲染使用单独函数。实时模块只向页面发布校验后的标准化快照，页面不直接解析原始接口响应。这样将来更换数据源时不需要重写页面。

## 验收与测试

- 交易时段边界：9:24、9:25、11:30、11:31、12:59、13:00、15:05、15:06。
- 周末、午休、收盘和手动刷新状态正确。
- 接口成功时指数、成交额、行业排行和明细同步更新。
- 空响应、超时、字段缺失、重复行业和过期快照均不会覆盖旧值。
- 选择历史日期时实时快照不修改历史页面；返回最新后可恢复。
- 页面切换和连续刷新不重复创建图表实例、不白屏、无控制台错误。
- 桌面宽度下排行、图表和明细表布局清晰；窄屏可横向查看表格。

## 成功标准

用户打开“天数据”即可看到时间明确、口径清楚的盘中市场与行业资金状态。任何无法确认的数据都显示为暂缺或延迟，不通过零值、成交额换算或其他方式补造资金流向。
